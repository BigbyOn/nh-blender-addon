# Журнал изменений

Все заметные изменения проекта фиксируются в этом файле.

## [0.6.10] - 2026-10-03

- Импорт Terrain Builder TXT сопоставляет имена template с путями P3D из `.tml`,
  даже когда имя template отличается от имени модели. Запись библиотеки имеет
  приоритет над поиском одноимённого P3D; неоднозначные и отсутствующие модели
  обнаруживаются до изменения сцены.
- В настройках аддона добавлена папка Terrain Builder template libraries:
  по умолчанию `P:\NH_Objects\TemplateLibs`, включая библиотеки в подпапках.

## [0.6.9] - 2026-10-02

- Корень проекта встроенного P3D-экспортёра по умолчанию — `P:\`, чтобы физические
  пути через junction экспортировались относительно игрового рабочего диска.

## [0.6.8] - 2026-10-02

- Импорт P3D, Apply и NH Materials используют общий кеш готового графа Super;
  недостающие данные рассчитываются и сохраняются, изменения исходников обновляют кеш.
- При импорте в фоне готовятся только недостающие сферы импортированных материалов.
  Убрано повторное декодирование PAA в обычном импорте.
- Экспорт сохраняет исходные `.paa` / `.rvmat`, включая рабочий диск через junction.
  Перенесённая карточка экспортируется с исходными путями ещё до подготовки шейдера.
- Calculate Previews завершает индикатор после остановки фонового Blender.
  Для сбоев добавлены Preview Error Details с полным описанием и путями исходников.
- Сохранение JSON-кеша повторяется при временной блокировке файла Windows;
  отдельные временные файлы защищают параллельную запись от конфликтов.

## [0.6.7] - 2026-10-01

- Добавлена **Calculate Previews** для расчёта всей библиотеки NH Materials:
  прогресс, счётчики обработанных материалов и ошибок, отмена с сохранением кеша.
- Повторный запуск использует готовые превью и пересчитывает только отсутствующие
  или изменённые. Расчёт продолжается вне Shading; Apply и перенос ставят его на паузу.
- Автоматический рендер при просмотре папок/поиске удалён. Refresh Library выполняет
  только индексацию; браузер обновляется после окончания ручного расчёта.

## [0.6.6] - 2026-09-30

- Ускорен NH Materials: Eevee, миниатюры 192px и отдельный кеш PAA mip512;
  полные текстуры и экспортные пути материалов сохраняются.
- Карточки объединены в ограниченные группы по папкам вместо отдельного `.blend`
  на каждый материал. Готовые превью сохраняются при миграции старого кеша.
- Повторное открытие использует готовый индекс; полный поиск новых файлов выполняет
  Refresh Library. Ожидающие карточки показывают серую сферу с отметкой Preview pending.
- Убраны постоянный пересчёт каталогов и поиск по всему индексу в UI-таймере.
  Обновления браузера выполняются пакетами после паузы worker; вне браузера он спит.
- Подготовка полных PAA для Apply и переноса в сцену выполняется в фоне.
  Материалы с одним fake user не обрабатываются; при переносе шейдер строится после
  завершения native drop, по одному материалу за цикл, с подготовкой NH_UV1.
- Добавлен выбор Preview engine: Eevee (по умолчанию) либо Cycles CPU с двумя потоками.

## [0.6.5] - 2026-09-30

- Исправлено включение аддона в Blender 4.0: регистрация библиотеки NH Materials
  перенесена из ограниченного контекста `register()` в таймер после включения.
- Настройка папки также обновляет библиотеку через таймер; ошибка её создания
  не прерывает включение аддона, а повторная попытка выполняется через 5 секунд.
- Проверки включения и интерфейса теперь используют `addon_utils.enable()`,
  включая отключение и повторное включение.

## [0.6.4] - 2026-09-30

- Добавлена библиотека **NH Materials** в Asset Browser рабочего пространства Shading:
  каталоги по папкам, поиск, пары цветовая текстура/RVMAT и ручной выбор цветовой текстуры.
- Добавлена настройка **NH Textures folder**, пустое значение использует `P:\NH_ObjectTextures`.
- Для Super создаются сферы под одинаковым студийным светом; рендер выполняется в фоне,
  превью кешируются и пересчитываются при изменении исходных файлов.
- **Apply Material** назначает материал выделенным объектам либо граням в Edit Mode.
- Импорт P3D использует общий Super-предпросмотр с Normal, Spec, Gloss и стадиями RVMAT.
  Удалены кнопка и оператор **Restore Material Preview**.
- Минимальная версия аддона изменена на **Blender 4.0.0**. Нативный P3D drag-and-drop
  требует 4.1+; в 4.0 доступны Add Files и File → Import. Кеши `.blend` разделены по
  версиям Blender для совместимости форматов.

## [Unreleased] - 2026-09-29

### Исправлено
- При экспорте геометрических LOD'ов (`Geometry`, `View Geometry`, `Fire Geometry` и других geometry-type) компоненты `Component##` теперь можно пересчитывать. Раньше экспортёр только добавлял компоненты при их полном отсутствии, поэтому устаревшие selections, импортированные из исходного `.p3d` (например, `zaton_refinery_building_A_p02_01.p3d` — 29 компонентов на 296 из 1675 вершин), молча экспортировались повторно, и модель выглядела «не пересчитанной». Новый флаг `recalculate_components` очищает старые `Component##` и заново строит их из замкнутых частей меша, как после ручного пересчёта (`zaton_refinery_building_A_p01_01.p3d` — 211 компонентов на все 2110 вершин).
- Selections компонентов в экспортируемом `.p3d` теперь всегда записываются в каноничном виде `Component##` с заглавной `C`: и пересчёт (`find_components`), и перенумерация (`P3D_LOD.renumber_components`), и `force_lowercase` сохраняют/восстанавливают заглавную первую букву, поэтому в файл больше не попадают `component01`, `component02` и т.д.

### Добавлено
- В **Import/Export Planner → Batch Export Collections (NH Internal P3D)** добавлена галочка **Geometry: recalculate components** (`export_recalculate_components`, по умолчанию включена): перед экспортом каждой модели для всех geometry-type LOD'ов (`Geometry`, `View Geometry`, `Fire Geometry`, geometry subtypes, `Underground`) существующие selections `Component##` заменяются на selections, построенные из замкнутых частей текущего меша. При выключенной галочке batch export сохраняет прежнее поведение и повторно использует существующие компоненты.
- В диалоге **NH Internal P3D export** (File → Export) добавлена опция **Recalculate Components** (`recalculate_components`, по умолчанию выключена) рядом с **Generate Components**; в **Batch Process P3D (Backup + Snap)** пересчёт компонентов включён всегда, так как после snap-сборки старые компоненты заведомо не соответствуют геометрии.
- Добавлены регрессионные проверки `tests/blender_component_recalc_validation.py`: пересчёт заменяет устаревшие компоненты замкнутыми частями, выключенный пересчёт сохраняет существующие selections, экспортный оператор и настройка batch export регистрируют новый флаг.

## [Unreleased] - 2026-09-28

### Исправлено
- После успешной сборки **NH Automatic Snap Magnet Check** для каждого собранного P3D root остаётся видимым только visual `Resolution 0`, а все остальные LOD'ы (`Resolution 1+`, `Memory`, `Geometry`, `Fire Geometry`, `View Geometry`, `Roadway` и другие служебные) скрываются во viewport через `hide_set`/`hide_viewport` — без удаления объектов и без изменения P3D-данных, vertex groups и материалов. LOD root скрывается целиком вместе с дочерними mesh/proxy-объектами; тип LOD определяется по A3OB LOD property, имя — только fallback. Если у root нет `Resolution 0`, видимость не меняется и выводится warning в System Console. После сборки viewport обновляется, результат логируется блоком `=== Assembly LOD Visibility ===`. Добавлены регрессионные проверки видимости.
- **NH Automatic Snap Magnet Check** переработан на локальную проверку по exact snap ID: каждый `.sp_<ID>_a_0/_1` и `.sp_<ID>_v_0/_1` проверяется независимо (A-пара в одном P3D root, V-пара в другом, ровно по одной вершине на точку, совпадение длин A/V в пределах epsilon, ненулевая длина). Удалены ложные ошибки глобальной цепочки: `Non-contiguous magnet IDs`, `Broken chain`, `Root participates in different snap chains`, `Root is A/V for multiple IDs`, `Cycle or repeated model detected`, сравнение длины всех магнитов с первым и запрет одинаковых координат разных ID. Настоящий дубликат exact ID (две A- или V-пары в разных roots) остаётся ошибкой. Лог теперь по каждому ID: PASS с A-root, V-root, обеими длинами и delta; FAIL с конкретной локальной причиной; без `CHAIN 1 / CHAIN 2`. Повторная перенумерация `.sp_` selections убрана — валидатор ничего не переименовывает. Односторонние коннекторы остаются предупреждениями и не блокируют сборку. Добавлены регрессионные проверки `tests/blender_snap_validation.py`.

### Добавлено
- В **P3D Tools & Checks → Export checks** добавлена кнопка **Auto-Fix N-gons (Scene)**: сканирует все mesh-объекты сцены тем же алгоритмом, что и **Report Meshes With N-gons**, и автоматически триангулирует n-gons из Object Mode — без ручного перехода в Edit Mode по каждому мешу. Общие mesh-данные обрабатываются один раз, объекты из linked library пропускаются, список исправленных и пропущенных объектов выводится в System Console. UV, материалы, custom normals и shape keys сохраняются.
- Там же добавлена кнопка **Auto-Fix Loose Verts (Resolution)**: удаляет isolated vertices без рёбер и полигонов (аналог Edit Mode → Mesh → Clean Up → Delete Loose) только в visual Resolution LOD, тоже из Object Mode. Дочерние меши LOD и объекты с общими mesh-данными обрабатываются один раз, результат выводится в System Console.
- В **Import/Export Planner → Batch Export Collections (NH Internal P3D)** добавлена галочка **Geometry: house properties + mass** (`export_geometry_house_metadata`, по умолчанию выключена). При включении перед экспортом каждой модели корневой A3OB `Geometry` LOD (token `6`, настоящий LOD root, без proxy) временно получает named properties `class=house` и `map=building` (значения заданы явно, не из `common_data["namedprops"]`) и корректный vertex layer `a3ob_mass`: при полном отсутствии массы создаётся исторический total mass `1000.0`, при частично нулевой — сохраняется существующая сумма и равномерно перераспределяется, при валидной массе ничего не меняется. Proxy children и остальные LOD не затрагиваются. Исходные Named Properties `.blend` восстанавливаются после экспорта существующим restore-механизмом; подготовка выводит отчёт в System Console. При выключенной галочке batch export работает как раньше.

## Сводный ченжлог: 0.6.2.7 → 0.6.3

Дата сравнения: **21 сентября 2026 года**.

Базовая версия — последний опубликованный [релиз NH Blender 0.6.2.7 от 3 сентября 2026 года](https://github.com/BigbyOn/nh-blender-addon/releases/tag/0.6.2.7), тег `0.6.2.7`, коммит `05da15af64c508b02400f0c6d1076ba60fbc4915`. Конечная версия — текущая локальная **0.6.3**, включая ещё не закоммиченные изменения. Ниже перечислены итоговые изменения относительно релиза; промежуточные варианты реализации объединены.

### Лестницы: Ladder Points

- Добавлен раздел **Ladder Points (Memory LOD)** под Snap Points: создание обычной лестницы или лестницы с промежуточным выходом по нижней, верхней и, при необходимости, средней ступеньке.
- Основной ввод упрощён: в Edit Mode достаточно выделить две планки для Standard или три для Middle Exit. Инструмент строго по мировой оси Z автоматически назначает Bottom, Middle и Top; одинаковые уровни отклоняются. Ручной выбор сохранён в сворачиваемом блоке.
- Ступеньки можно задавать отдельными мешами, захватывать из двух выделенных объектов или из выделенных частей меша в Edit Mode.
- Верхний выход выбирается тремя кнопками **Front / Left / Right**. Front отключает Left/Right; боковые кнопки отключают Front и могут быть активны по отдельности или вместе. У промежуточного выхода Left/Right работают независимо. Создаются соответствующие группы `ladderN`, включая общие вершины нескольких групп, по структуре `laddernest`.
- Добавлены ручной ID и автоматический выбор номера, свободного в Memory и View Geometry. Кнопка **+** подготавливает создание следующей лестницы.
- Одновременно с Memory-точками создаётся замкнутый бокс во **View Geometry**: 8 вершин, 6 граней, группы `ladderN` и `ComponentXX`. Отсутствующие LOD создаются автоматически.
- Повторное создание с тем же ID обновляет его точки и бокс без дубликатов, сохраняя остальные лестницы. При ошибке изменения обоих LOD откатываются; общие mesh-данные отделяются от других объектов перед изменением.
- Настраиваются сторона подхода и её разворот, высоты входов и точек взаимодействия, подъём бокового выхода, глубина и запас бокса. Параметры сохраняются в `.blend`.

### Fake Terrain

- Генерация переделана под набор отдельных замкнутых выпуклых компонентов, приближающих поверхность визуальной модели.
- Добавлены независимые настраиваемые допуски **над и под поверхностью**; значения по умолчанию — по 0,10 м. Контролируется ошибка готовой выпуклой геометрии, а не только исходных патчей.
- Учитываются отверстия, вогнутые участки и раздельные уровни поверхности; исправлена обработка вогнутых полигонов.
- Ограничиваются сложность каждого компонента и перепады на границах соседних участков. Простые участки объединяются, более сложные требуют большего числа компонентов.

### Cylinder, Pipe и редактор пайпов

- Cylinder и Pipe используют общий анализ реальной геометрии: распознавание колец по вершинам и рёбрам, с резервным определением оси по распределению точек. Исправлены ошибки ориентации при работе только по bounding box.
- Добавлен ручной выбор оси для неоднозначных форм; улучшена обработка тонких колёс и несовпадающего поворота внутреннего и внешнего контуров.
- Pipe получил постоянный редактор: **внешний и внутренний диаметры, глубина, количество и поворот сегментов**.
- Рабочая последовательность: **Create Pipe → редактирование → Pipe to Boxes**. Изменение параметров обновляет существующий пайп и не накапливает старые объекты и mesh-данные.
- Конвертация создаёт отдельные замкнутые прямоугольные боксы с сохранением отверстия и удаляет вспомогательный пайп после успеха. Учитываются трансформации и поддерживается несколько выбранных пайпов.
- Повторная конвертация не принимает готовые боксы за новый исходник. Ошибки конвертации откатывают изменения LOD и сохраняют редактируемые пайпы.

### Convex Hull и остальные коллайдеры

- Добавлен **Hull Selected Vertices**: построение оболочки непосредственно по выделенным вершинам в Edit Mode.
- **Re-Convex** строит точную оболочку по всем вершинам выбранных компонентов без предварительного отбора экстремальных точек.
- Для упрощения Hull добавлен настраиваемый предел отклонения формы. Нулевой бюджет треугольников соответствует точной оболочке; невозможное сочетание бюджета и допустимой ошибки не применяется молча.
- Исправлена сварка при добавлении геометрии: соприкасающиеся выпуклые компоненты остаются независимыми.
- Добавлен откат при ошибке Rebuild и многокомпонентной генерации.
- Исправлены ориентация граней на полюсах Sphere/Capsule и дублирование экватора Capsule. Выравнивание Capsule по источнику использует реальные точки; подбор ориентированного бокса учитывает мировой масштаб.

### Проверка геометрии

- Добавлен **Geometry Audit** для Geometry, Fire Geometry и View Geometry: подсчёт компонентов, поиск вершин и островов без граней, мелких компонентов и подозрительных вложенных оболочек.
- Результаты доступны отдельно по LOD; команды **Select Faceless / Tiny / Nested** выделяют найденную геометрию для проверки.
- **Clean Safe Garbage** удаляет только предусмотренные безопасные категории мусора; подозрительные вложенные оболочки автоматически не удаляются. Shared mesh отделяется от невыбранных копий.
- Расширен **Collision QA**: проверка нулевых площадей и объёмов, выпуклости, дублирующихся граней и пересечений несмежных граней.
- Ускорены пространственные проверки Geometry Audit с использованием BVH.

### Snap Points и сборка моделей

- ID snap-пар выбирается автоматически по существующим группам Memory. Создание проверяет две выбранные позиции и наличие соответствующих вершин в обоих A/V targets с настраиваемым допуском **Target Match Distance**.
- Выбранные A/V targets сохраняют своё назначение; при некорректном выделении создание останавливается до изменения Memory.
- Кнопки **X/Y/Z** одновременно выбирают ось сортировки точек 0/1 и включают её в имя. Повторное нажатие активной оси выключает суффикс и делает кнопки серыми; последняя ось сортировки сохраняется.
- Убран отдельный флажок Include Axis in Name. Вместо поясняющих надписей показано превью четырёх полных имён с ближайшим свободным ID; объяснения перенесены в подсказки при наведении.
- Добавлен **Snap Magnet Check / Check & Assemble Visual LODs**: поиск snap-цепочек, пропущенных и повторяющихся ID, неполных пар, несовпадающих расстояний и разрывов соединений.
- Сборка перемещает только visual Resolution LOD. Поддерживается восстановление последовательности старых повторяющихся ID по порядку частей `_p01_`, `_p02_` и далее.

### Terrain Builder TXT, P3D и материалы

- Добавлен импорт **Terrain Builder TXT** в Import/Export Planner и меню File → Import: поиск исходных MLOD P3D, перенос координат, yaw/pitch/roll и масштаба, выбор начала координат, связанные или независимые копии.
- Импорт TXT учитывает центр габаритов LOD по XY для стыковки секций. Данные проверяются до расстановки; при ошибке созданные объекты откатываются, очередь Planner сохраняется.
- Встроенный **NH P3D backend** стал приоритетным; внешний Arma 3 Object Builder остаётся резервным вариантом.
- Drag & Drop `.p3d` сразу добавляет файлы в очередь Planner и обновляет интерфейс.
- Добавлено исправление распознанных больших смещений импортированных Resolution/Geometry/Roadway относительно Resolution 0. Memory сохраняет своё положение; число исправленных LOD выводится в отчёте.
- Batch Export сохраняет мировые трансформации и исходную видимость объектов и коллекций.
- Улучшен поиск текстур относительно исходного `.p3d`, включая проектные пути и повторяющиеся сегменты каталогов.
- Добавлен **Restore Material Preview** для восстановления превью материалов выбранной P3D-модели.

### Прочие исправления и проверки

- Исправлен **Select Shell** в multi-object Edit Mode: выделение теперь ищется во всех редактируемых мешах, поэтому полигон на неактивном объекте больше не игнорируется. Связанные оболочки разворачиваются без зависимости от активного объекта.
- Раздел Fixes переименован в **P3D Tools & Checks**; исправлена повреждённая кириллица в названиях и подсказках.
- Исправлено восстановление трансформаций при удалении Plain Axes. Вариант **Save Z** сохраняет высоту visual Resolution 0 и согласует высоту остальных LOD.
- В Model Split точки и прокси на границах частей получают одного владельца, что предотвращает их дублирование.
- При обновлении ZIP в работающем Blender перезагружаются модули и удаляются устаревшие зарегистрированные классы, чтобы старый интерфейс не оставался вместе с новым кодом.
- Добавлены проверки импорта TXT, генерации коллизий и terrain, редактора Pipe, Undo/Redo и лестниц. Финальная сборка лестниц прошла 18 проверок Blender, включая переключение выходов, автоматическую сортировку 2/3 ступеней по мировой Z, сравнение с пользовательским `laddernest` и обновление обоих LOD.

### Проверка в игре

Геометрия и структура данных проверены в Blender. Анимации лестниц и поведение коллизий непосредственно в DayZ не проверялись. Смещения Ladder Points настраиваются под уровни пола и площадок; размеры Geometry/Roadway и конфигурация здания остаются частью подготовки конкретной модели.
